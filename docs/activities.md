# 独立活动报名

入口 `/activities`。在现有后台权限管理或用户权限编辑中勾选“活动管理”（`manage_activity`），也可通过全局角色 `activity_manager` 授予。该权限允许管理全部独立活动，不自动授予后台工作区、用户管理、比赛管理权限。全站管理员和站长也可管理活动，仍遵循现有权限策略。

## 使用流程

活动列表支持名称/地点搜索，以及报名中、即将开放、我的报名、已结束、管理者草稿筛选。筛选由服务器执行并写入 URL，跨页结果一致。

“我的报名 / 邀请”同时包含待接受的邀请，活动行直接提供处理邀请或查看报名入口；管理者可见待审核数量及管理入口，不显示个人报名入口。活动详情的管理页签与概览靠左排列。普通用户在概览的活动安排下方可点击“开始报名”，已有报名或邀请时显示对应操作，不再使用整行提示色块。表单仅显示必填完成度，不显示“继续填写”按钮。

管理者在前台按“基本信息 → 报名规则 → 报名表单 → 预览与发布”创建活动；每步验证必填与时间范围，表单支持常用问题快捷添加和实时填写效果预览。日期选择沿用公告组件，24 小时制，包含小时、分钟下拉选项；活动时间按北京时间输入和展示。草稿仅管理者可见，发布后按开放时间接受报名，关闭后保留公开介绍与本人报名。

个人直接填写完整表单并一次提交；服务器在同一事务内创建、校验及提交，失败不留下空报名。已有填写中/退回记录也可以在提交时原子保存本人答案。队长建队、邀请用户名；队员主动接受，分别保存确认本人信息，队长才能整队提交。界面明确显示人数、待确认成员及提交条件，提交同时保存队长当前表单；其他成员不完整时整次操作回滚。邀请、移除、刷新成员保留本人未保存的输入，离开页面提示未保存内容。邀请在活动页显示并通过系统通知提醒，不发送邮件。每位成员的实名资料和答案仅本人和活动管理者可见，队友只见用户名及完成状态。

报名状态为填写中、待审核、报名成功、退回修改、已撤回。不需审核时提交即成功。已通过或待审核的答案、队名实际变化会重新进入审核；重复保存相同内容保留审核状态。退回与拒绝合并为“退回修改”，可在报名开放期修改重交；历史 rejected 记录在详情、列表、筛选、计数和导出中统一按 returned 处理，原审核说明保留，旧客户端提交 rejected 也按退回处理，不批量改写历史记录或补发通知。个人修改后直接重新提交，组队仍由队长提交。队员可在截止前退出，退出使整队回到填写状态。队长可在填写中或退回时移除成员；整队已提交时可撤回整队报名。撤回释放全部成员报名资格并保留管理名单中的快照。

“我的报名”只保留“填写报名信息”和“报名结果”两个进度阶段；退回后重新回到填写阶段。待审核或已成功的报名显示结果与审核说明，用户点击“修改报名信息”后才进入编辑。

活动介绍使用全站统一的 Markdown 编辑器，支持源码、分屏预览、即时渲染及所见即所得模式。切换配置步骤和保存设置时同步内容；报名答案及审核说明保持普通文本输入。

报名管理仅展示每位用户当前的报名状态：撤回后重新报名或加入其他队伍，旧记录中的该成员不再重复展示；未重新报名者显示最近一次撤回状态。组队按队伍汇总，展开后切换成员查看资料，右侧直接审核。同一时间只展开一条报名详情，打开另一条会收起当前条目；尚未保存的审核内容保留。状态筛选保留全部、待审核、报名成功、退回修改和已撤回，填写中的记录仍可在全部列表查看。状态数量、搜索、分页和 CSV 均使用相同的最新记录范围，历史快照仍保留。待审核报名必须明确选择通过或退回修改，退回必须填写说明；保存后保持展开位置，其他报名未保存的审核内容在版本未变化时保留。

管理名单默认待审核优先，同为待审核时按提交时间从早到晚排列，也可切换最新报名优先。“开始审核”进入待审核范围，“保存并审核下一份”保存当前选择后打开下一份，保持搜索条件；不会自动选择审核结论。结果变少时页码自动回到有效范围。

系统通知覆盖报名提交、免审核报名成功、审核通过及退回修改。个人通知本人，组队结果通知所有当前确认成员；退回附审核说明。邀请通知被邀请人，接受邀请通知队长。通知进入现有通知中心并增加未读数，可直接打开对应活动的“我的报名”。通知与报名、审核及邀请操作在同一事务写入，并发布到用户通知事件流；重复邀请和结果及说明均未改变的审核不重复通知。历史状态不补发，报名答案不会写入通知。

活动配置提供个人活动、组队竞赛、培训招新模板；应用模板保留活动名称、介绍和时间，已有问题时先确认替换。最后一步集中核对介绍、地点、已过截止时间和活动时间早于报名截止等情况，非必填信息缺失不阻止保存。

报名表和活动配置输入自动暂存于当前标签页的 `sessionStorage`，按用户、活动、表单隔离，有效期 24 小时；刷新后由用户点击恢复或丢弃。草稿不调用写接口、不占报名资格、不自动提交，成功保存或提交后清除。活动配置版本变化、本人报名或答案变化时不再恢复旧草稿；队友更新资料不会覆盖自己的输入。关闭标签页即清除暂存，存储不可用时界面显示失败状态。

管理者可查看各状态总数，按状态进入名单，搜索用户名、实名、学号、队名及答案文本，筛选状态，展开完整信息，逐条审核或导出 Excel 可读 UTF-8 CSV。导出包括筛选结果，单次最多 10000 份报名，学号保留为文本，防止公式执行。复制活动只复制设置与表单，生成草稿，不复制报名记录。活动配置中提供“删除活动”，需全局管理权限、最新修订号及准确活动名称；事务中将活动标记为 deleted 并记录审计。删除后列表和所有详情/报名/审核/导出接口均不可访问，历史报名数据保留，不物理删除。

## 界面结构

采用 OJ 现有明暗主题与单一强调色，列表用日期和活动标题建立层次。活动概览以介绍为主、报名安排为辅；报名页以个人表单为主、队伍进度为辅；配置按步骤展开，表单旁显示实时预览。步骤切换与审核详情展开使用轻量过渡，按钮状态过渡提示可操作区域，尊重减少动画设置。手机端改为单列，不横向挤压表单。

移除标题、表单和按钮附近的解释性小字；仅保留必要的字段标签、状态、时间和操作反馈。草稿、缺项、发布检查和连续审核控件仅在适用时出现。

## 数据与约束

- `activity`：活动设置、表单 schema、修订号。
- `activity_registration`：个人报名或队伍、队长、状态、审核说明、成员信息快照、修订号。
- `activity_member`：当前确认成员、身份快照、本人答案和确认状态。`(activity_id,user_id)` 主键及 `(activity_id,student_id)` 唯一索引阻止同一人重复报名。
- `activity_invitation`：待确认邀请。邀请不占用报名资格，加入任一队伍后清理该活动中本人其他邀请。

所有变更先锁活动行，在同一事务内检查时间、状态、修订号并写审计和事件。报名开始时间包含该时刻、截止时间不包含该时刻；审核可在报名截止后进行。报名和审核写入携带所显示的 `revision`，并发旧版本拒绝，保留客户端当前输入供用户核对。接受邀请使用活动锁检查实时成员数与唯一约束。临时比赛账户不允许报名，用户身份从服务器实名资料获取，提交内容不能覆盖。

已有任意报名记录后，方式、人数、审核规则和全部字段结构锁定，仍可修改介绍、地点、时间和关闭状态；不允许将已有公开报名的活动退回草稿。需要变更表单时复制新活动。活动数据不关联比赛评测、比赛报名或账号生成。

## 验证和部署

`npm test` 包含基础验证与权限矩阵；`npm run test:activities:mysql` 使用随机前缀的独立测试表并最终删除，验证真实 MySQL 事务和并发；`npm run test:activities:browser` 需要 Playwright 和 Chromium，使用离线 API fixtures 检查页面流程、时间选择与移动端溢出。

最新报名视图使用窗口函数和 `JSON_TABLE`，需要 MariaDB 10.6 或更高版本（部署环境为 MariaDB 12.3）。查询只投影当前成员，不迁移或删除历史记录。

新增模块、库、模板和静态文件在 Compose 中单独挂载。v2.4.0 为 Web 更新，构建并重新创建 Web 容器即可，评测端保留原镜像。首次访问创建四张独立 InnoDB 表；不改动现有比赛表。帮助页自动追加活动报名章节，不覆盖已编辑内容。回退 Web 代码可保留活动表，恢复此版本后可继续使用。
