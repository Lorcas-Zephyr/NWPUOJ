# 周赛总榜

总榜直达 `/weekly-ranklist`；设置页 `/weekly-ranklist/settings`。全站侧边栏、首页等导航不显示总榜入口，可由管理员在比赛公告放置链接。
只有站长、全站管理员可以选择比赛、管理总榜名单、登记线下参赛和主动重算。普通用户只能查看总榜，不会收到姓名、学号字段；管理员可切换显示真实信息。临时比赛账号继续使用原有受限导航。

## 名单与比赛

- 添加已有普通账户，支持用户名 / UID / 学号 / 姓名搜索、班级搜索导入、学号 CSV 导入。三种方式合并去重，不创建账户，也不代报名比赛。
- 班级导入取导入时的成员快照；未来班级变更不自动改变总榜名单。
- CSV 为 UTF-8，一列十位数字学号，可有「学号」表头，每次最多 1000 人、1 MiB；同一文件不能重复学号。未匹配学号会显示，已在总榜的成员跳过。
- 比赛按名称或编号搜索，只加入 ACM 比赛，按开始时间先后排列。未结束比赛只显示占位，不提前发布成绩；被改为非 ACM 的比赛暂停计分并在设置中提示。
- 移除比赛或成员会同时删除它在本总榜的线下登记，不删除原比赛、账户、提交，不改变比赛报名或 Rating。

## 计分

默认采用已确认的规则：**N 为总榜全部成员数，包括该场缺席和零通过成员；缺席不计入 G2 分母。**

1. 单场重新在总榜成员中统计通过数和罚时，按通过数降序、罚时升序排名；完全相同采用并列名次（1、1、3）。不使用原比赛名次，不受总榜外选手影响。
2. 单场积分 = `100 × (本人通过数 / 第一名通过数) × (2N − 2) / (N + 名次 − 2)`。零通过为 0；N=1 且通过至少一题时按第一名上限 200 分处理，避免 0/0。
3. 取已结束、线下参赛的最高四场积分累计为 S1，`G1=S1/4`，不足四场仍除以四。相同积分优先较早比赛，仅决定分组颜色，不改变总分。
4. 本人其余实际参赛场次累计为 S2，`G2=S2/实际场数`，无场次时为 0。多于四次线下时，未入选 G1 的线下场次也加入 G2。
5. `总分=60%×G1+40%×G2`。计算全程保留精度，页面展示两位小数；排序按未舍入总分，并列采用竞争排名。

设置页明确显示人数与缺席计分口径；管理员更改口径后会重算所有成员和场次。

## 线下核验与实际参赛

线下登记页以成员为行、比赛为列，勾选后保存。由管理员核实机房现场、机房电脑、禁止联网等要求，系统不根据 IP 自动判断，不检测用户网络连接。

「实际参赛」指该场比赛时间内存在未取消的提交，或被管理员登记为线下参赛。仅报名但没有提交、也没有线下登记时按缺席处理。线下有到场但无提交时仍记一次线下，得零分。取消线下标记后，有赛时提交则按线上参赛，否则视为缺席。作弊导致该场零分，但仍保留参赛场次，不能通过作弊标记把零分变成缺席。

榜单每个场次单元格使用近透明浅蓝表示 G1、浅绿表示 G2；小字标记线下 / 线上 / 缺席，并显示「通过数/总题数」（例如「线下 · G1 · 通过 5/10」）。总题数随比赛当前题目列表更新；未结束比赛的通过数显示「—」，不提前披露成绩。每页 100 人，支持筛选，宽表在容器内横向滚动。

## 一致性与部署

- 名单、比赛、线下记录或规则变更在同一事务内锁定总榜版本、保存并完整重算。过期版本返回 412，不覆盖其他管理员的修改。
- 页面同时发送 If-Match 请求头和请求体版本，兼容外网网关移除响应头的情况；CSV 同时发送 CSRF 请求头。
- 数据源来自赛时提交，排除赛后练习、取消评测、移除报名者，并按作弊记录将该选手本场清零。
- 服务器共享每 30 秒检查赛后结果，重测、修改比赛时间/题目/标题、修改用户名或删除用户也会触发数据源变化；浏览页每 30 秒同步。
- 使用独立 `weekly_ranklist*` 数据表，首次部署为空，不擅自挑选真实名单或比赛。新增挂载后需只重建 web 容器生效，不重启评测机、数据库或队列。
